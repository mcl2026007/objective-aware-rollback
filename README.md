# Objective-aware rollback validation for agentic systems

A deterministic, CPU-only simulator study of objective-version validation and durable-effect idempotency around checkpoint restore and action commit.

> **Research prototype, not a production safety mechanism.** This repository models policy behavior in a local simulator. It does not connect to a real LLM, tool provider, database, payment system, or external service.

## Problem statement

Checkpoint/rollback can restore an agent's internal state without necessarily reverting external effects or updating the authorization context under which an action was prepared. If the objective changes after a checkpoint, a resumed agent may attempt an action based on a superseded objective or stale authorization.

This project tests whether a pre-commit gate that checks objective version **and generation/epoch** can reject stale actions, and whether a separate durable effect ledger/idempotency check can prevent duplicate effects on retries.

The experiment uses four deterministic policies:

- **B0 — unguarded baseline:** resumes and commits without the proposed objective-version gate.
- **B1 — objective/epoch gate:** validates action, authorization, and restored-agent objective metadata against the trusted current objective/generation.
- **B2 — scripted re-plan comparator:** uses a scripted oracle to re-plan; it is **not** an LLM planner.
- **B3 — gate + idempotency:** combines generation-aware validation with a durable-effect duplicate check.

The simulator contains 140 scenario templates: 40 development templates (F1–F10) and 100 held-out-labelled templates (F11–F15), evaluated under four policies (560 policy–scenario runs).

## Limitations and interpretation

1. **Simulator-only:** no real LLM, agent framework, external tool, database, or production rollback system is evaluated.
2. **Encoded policy contrast:** policy behavior is explicitly implemented in code; the outcomes demonstrate conformance to the modeled rules, not independent proof of real-world safety or causal effectiveness.
3. **Designed cases, not independent samples:** the 100 held-out-labelled templates are designed challenge cases, not repeated stochastic trials or a statistically sampled population. Structural-signature non-overlap does not prove semantic independence or broad generalization.
4. **B2 is not an LLM baseline:** it uses a scripted oracle.
5. **Idempotency is separate:** objective-version validation alone does not prevent duplicate side effects; the held-out split has no duplicate-retry cases.
6. **No production guarantees:** simulator-side durable effect IDs do not prove distributed exactly-once execution, transactional rollback, or external side-effect reversal.
7. **No performance claims:** simulator-step counts are not wall-clock latency, CPU utilization, memory use, or production overhead.
8. **No inferential statistics:** one deterministic run with template cases; no confidence intervals, p-values, or significance claims are justified.
9. **Environment scope:** final frozen artifacts are recorded as Python 3.12.3 / Windows 11 / CPU-only, but the old Windows execution log refers to a prior three-policy/420-run candidate. A clean Windows rerun of this exact four-policy/560-run repository remains **[TEST REQUIRED]**.
